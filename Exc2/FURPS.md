| Код  | Требования                         | Комментарий  |
|------|------------------------------------|--------------|
| F    | Функциональные (Functionality)     |              |
| F1   | Пользователь должен иметь возможность просматривать перечень доступных депозитных продуктов на сайте  | Обеспечивает прозрачность условий для клиентов |
| F2   | На сайте должна быть реализована подача заявки на открытие депозита | Упрощает процесс оформления, снижая нагрузку на офисы банка |
| F3   | В интернет-банке пользователь должен видеть список доступных депозитов с учётом персональных условий  | Персонализация предложений повышает лояльность клиентов |
| F4   | В интернет-банке должна быть реализована функция оформления депозита | Позволяет клиенту открыть депозит без визита в офис |
| F5   | Подтверждение открытия депозита в интернет-банке должно выполняться через SMS | Дополнительный уровень безопасности для защиты средств клиента |
| F6   | Весь процесс согласования условий депозита должен обрабатываться в АБС | Централизация обработки данных для надежности и консистентности |
| F7   | После подтверждения условий депозита и его открытия клиент должен получать уведомление по SMS | Информирование клиента о статусе его операции |
| U    | Удобство использования (Usability) |              |
| U1   | Визуальный стиль интерфейса должен соответствовать корпоративному дизайну банка | Гарантирует единообразие пользовательского опыта |
| R    | Надёжность (Reliability)           |              |
| R1   | Система должна быть доступна круглосуточно (24/7) | Критически важно для онлайн-сервисов банка |
| R2   | Минимальный уровень доступности сервисов — 99,9% | Требование высокой доступности для исключения сбоев в работе системы |
| R3   | В случае отказа дата-центра интернет-банк должен оставаться доступным, выдерживая нагрузку 20 RPS, а АБС — 40 RPS (значения ориентировочные) | Обеспечивает отказоустойчивость и бесперебойность обслуживания |
| P    | Производительность (Performance)   |              |
| P1   | Операции должны выполняться с минимальной задержкой (миллисекунды) | Важно для комфортного пользовательского опыта |
| P2   | Серверная инфраструктура должна поддерживать горизонтальное масштабирование | Позволяет наращивать мощности в зависимости от нагрузки |
| S    | Поддерживаемость (Supportability)  |              |
| S1   | Должна быть подготовлена документация для дальнейшего развития системы | Облегчает сопровождение и интеграцию новых функций |
| +R   | Ограничения (Restrictions)        |              |
| +R1  | Предпочтительно использовать уже существующие в банке технологии | Минимизирует затраты на внедрение и поддержку |
| +R2  | Новые технологии могут внедряться при условии совместимости с текущими платформами разработки | Обеспечивает постепенную эволюцию системы без серьезных переделок |
| +R3  | Желательно, чтобы в банке уже была экспертиза по внедряемым технологиям | Ускоряет процесс внедрения и снижает риски ошибок |
| +R4  | Некоторые справочные данные при проведении платежей загружаются дольше одной секунды | Следует учитывать это при проектировании интерфейса и логики обработки |
| +R5  | Интернет-банк не должен напрямую взаимодействовать с API АБС в новом процессе | Повышает безопасность и снижает зависимость систем друг от друга |
| +R6  | Разработка и поддержка SMS-функционала должна осуществляться силами внутренних команд | Внесение изменений в ядро системы может быть сложным или потребовать длительного времени |
| +R7  | Масштабирование АБС возможно только вертикально | Из-за использования реляционной базы данных, которая плохо масштабируется горизонтально |
| +R8  | При выборе брокера сообщений предпочтение следует отдать Kafka | Kafka является надёжным и широко используемым решением, что обеспечит стабильность работы |
| +R9  | Избегать прямого взаимодействия интернет-банка с API АБС в новом процессе | Разделение логики между системами снижает риски отказов |

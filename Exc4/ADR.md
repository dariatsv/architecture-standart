# Функциональные требования

| №  | Участники | Use Case                        | Описание  |
|----|----------|---------------------------------|-----------|
| 1  | Клиент   | Запрос информации              | Обращается в кол-центр для получения сведений о депозитных ставках. |
| 2  | Кол-центр банка | Консультация по ставкам  | Оператор проверяет актуальные данные и передаёт информацию клиенту. |
| 3  | Партнёрский кол-центр | Запрос информации | Получает актуальные данные и сообщает их клиенту. |
| 4  | АБС и подсистема депозитов | Обновление данных | Формирует и передаёт файлы с актуальными ставками для использования в кол-центрах. |
| 5  | IT-отдел | Поддержка системы | Обеспечивает стабильную работу системы, обновляет информацию и устраняет технические неполадки. |

# Нефункциональные требования

| № | Требование                                                    |
|---|---------------------------------------------------------------|
| 1 | Защищенность данных                        |
| 2 | Высокая доступность (99.9%)                                   |

## Решение

Оптимальным вариантом для взаимодействия с партнёрским кол-центром является использование SFTP-протокола. Он позволяет быстро, безопасно и без лишних затрат передавать необходимые данные.

## Реализация

Развёртывание API-доступа или интеграция с облачными сервисами (например, S3) в рамках MVP нецелесообразны с экономической точки зрения.

## Альтернативы

Можно рассмотреть возможность передачи данных через API, что позволит ускорить процесс их обновления между кол-центрами.

## Возможные риски и ограничения

- Скорость обновления данных между кол-центрами может быть ниже при использовании файлового обмена.
- Возможны сбои при передаче файлов, что напрямую влияет на оперативность взаимодействия с клиентами.
